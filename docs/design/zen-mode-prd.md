# PRD — Zen Mode 禅模式

- **项目：** Nuvyn
- **模块：** Vault / Note / Diary
- **日期：** 2026-10-11
- **状态：** Draft / 待评审
- **优先级：** P2
- **类型：** 新功能

---

## 1. 需求概述

### 1.1 功能定义

Zen Mode（禅模式）是 Nuvyn 提供的一种临时沉浸式写作与阅读状态。

进入禅模式后，Nuvyn 隐藏与当前文档内容无直接关系的界面元素，将用户的注意力集中在正文区域。

禅模式不创建新的编辑器、不复制文档、不改变文档数据，也不接管现有保存或恢复机制。

**核心原则：隐藏界面，而不是切换工作区。**

### 1.2 设计目标

1. 减少写作和阅读过程中的视觉干扰。
2. 保留现有编辑器完整的编辑、保存与恢复能力。
3. 支持快速进入与退出，并精确恢复原有界面状态。
4. 保持 Note 与 Diary 一致的沉浸式体验。
5. 以最小的架构和交互成本实现功能。

### 1.3 非目标

第一版不实现以下功能：

- 浏览器全屏模式（Fullscreen API）。
- 独立的 Zen Editor 或额外文档副本。
- 打字机滚动（Typewriter Mode）。
- 当前段落高亮、其他段落淡化。
- 专注计时器、白噪音、背景音乐。
- 专门的禅模式主题配置。
- 新的自动保存、草稿或历史机制。
- Board、Ledger 的禅模式适配。

## 2. 用户场景

### 场景 A：Note 专注写作

用户正在编辑一篇 Markdown 笔记，希望暂时隐藏文件树、工具栏、AI 面板与状态栏，只保留居中的编辑器。

进入禅模式后，用户继续在原有 Monaco Editor 中输入内容。

退出时，所有辅助面板恢复到进入前的状态。

### 场景 B：Diary 沉浸式记录

用户通过 Diary Calendar 打开当天日记，进入禅模式后专心写作。

日记的解锁会话、单文档策略、编辑内容和自动保存不受影响。

退出禅模式后，恢复原来的 Diary 文档界面。用户仍可以通过顶部日期按钮返回日历。

### 场景 C：专注阅读

用户在 Note 阅读模式中进入禅模式。

正文保持 Markdown 渲染效果，包括图片、表格、代码块、Mermaid、MarkMap 和数学公式。

退出时仍处于原来的阅读模式。

## 4. 交互设计

### 4.1 进入禅模式

V1 不增加常驻 NavBar 按钮。

保留现有快捷键入口：

`Ctrl/Cmd + K → Z`

快捷键不会因 Logo 入口或移动端支持而改变。早期草案曾提出 `Alt + Shift + Z`；核对现有实现后，V1 实际使用的是上述两段式快捷键，本次增量不覆盖或重设该决策。

进入时：

1. 确认当前文档符合禅模式条件。
2. 保留当前 Workspace 和文档状态。
3. 隐藏辅助 UI。
4. 扩展正文容器。
5. 将输入焦点保持在当前编辑器，或转移至正文阅读区域。

不触发保存、刷新、路由切换或重新加载文档。

当前实现还提供不常驻显示的 Logo 星座入口：桌面端在 NavBar Logo 区域悬停 3 秒，手机和平板长按 3 秒。符合禅模式条件时，九德动画每 600ms 启动一颗有限 SVG 粒子，并在同一节拍切换对应词汇；粒子约 540ms 内缓动至中心圆的可见边缘。粒子的 `endEvent`（或基于实际时长的 watchdog 恢复）只标记抵达，不负责切词；最后一颗抵达后，「清明 / Clarity」再停留约 800ms，星座背景淡出，淡出完成时再次校验当前文档资格并进入禅模式。光环、连线和其他循环动画不作为完成条件。触屏长按成功后用户可以立即松手，九德动画继续播放。非资格页面不会进入禅模式；桌面装饰性星座仍由离开 Logo 关闭，触屏触发的星座则在动画完成后自动淡出。

在不支持禅模式的页面上，Logo 仍可展示原有品牌动画，但不会进入禅模式。普通点击 Logo 继续执行首页导航；Logo 入口不增加常驻按钮。

### 4.2 退出禅模式

支持以下方式：

- 按下 `Esc`。
- 再次使用禅模式快捷键。
- 离开当前文档或进入其他 Workspace 时自动退出。

退出后恢复普通布局。

### 4.3 Escape 优先级

`Esc` 必须遵循现有交互优先级。

1. IME 输入法组合输入过程中，不退出禅模式。
2. Monaco 自动补全、搜索框、悬浮交互等需要优先关闭的浮层，应先处理自身的 Escape。
3. 已打开的确认弹窗、菜单或其他模态界面优先处理 Escape。
4. 不存在更高优先级交互时，Escape 才退出禅模式。

例如，Monaco 自动补全正在显示时，第一次 Escape 关闭补全，之后再按 Escape 才退出禅模式。

不允许使用无条件的全局 Escape 监听破坏现有行为。

## 5. 界面设计

### 5.1 元素可见性

| 界面元素 | 普通模式 | 禅模式 |
| --- | --- | --- |
| NavBar | 显示 | 隐藏 |
| ActivityBar | 显示 | 隐藏 |
| FileTree / 左侧面板 | 按用户设置 | 隐藏 |
| RightRail / AI / TOC | 按用户设置 | 隐藏 |
| EditorTabs | 按当前规则 | 隐藏 |
| StatusBar | 显示 | 隐藏 |
| 文档阅读区 / 编辑区 | 显示 | 显示 |
| 系统标题栏 | 原样 | 原样 |
| 浏览器地址栏 | 原样 | 原样 |

禅模式隐藏的元素不应保留空白布局占位。

### 5.2 正文布局

桌面端正文采用居中布局。

设计参考值：

- 正文最大宽度：约 800px。
- 左右保留对称空白。
- 顶部留出舒适的阅读空间。
- 高度使用可用工作区。
- 内容超出高度时沿用现有滚动行为。
- 窄桌面窗口下自然缩小内容宽度。
- 不产生额外的水平滚动条。

这些数值为视觉参考，不要求使用固定像素强制覆盖现有编辑器排版系统。

### 5.3 编辑模式

保留原有 Monaco Editor。

要求：

- 保留光标和选区。
- 保留撤销 / 重做历史。
- 保留滚动位置。
- 保留 Markdown 编辑辅助能力。
- 保留当前字号、行高等用户偏好。
- 不重新创建 Monaco Model。
- 不因容器切换清空未保存文本。

禅模式仅改变编辑器所在容器的可视空间。

### 5.4 阅读模式

保留现有 ReadingPane 与 Markdown 渲染机制。

不重新解析或修改 Markdown 源文档。

允许响应容器尺寸变化，完成已有图表和图片的布局适配。

### 5.5 视觉反馈

禅模式使用当前 Nuvyn 主题，支持 Light / Dark。

V1 不设计独立的背景、渐变、阴影或动态动画。

不展示持续存在的“正在禅模式”工具栏。

可在首次进入时提供一条短暂、非阻塞的退出快捷键提示，但不是必需项。

## 6. 状态管理

### 6.1 临时状态

禅模式是 UI 层临时状态。

不得写入：

- 文档 Markdown 内容。
- 文档 Frontmatter。
- 文档元数据。
- Git History。
- Ledger / Diary 业务数据。

V1 不将禅模式作为持久用户偏好。

刷新页面后恢复普通布局。

### 6.2 原始布局恢复

进入禅模式时，不得通过修改并覆盖现有侧栏偏好来实现隐藏。

例如：

- 原本展开的 FileTree，退出后仍展开。
- 原本关闭的 RightRail，退出后仍关闭。
- 原本处于阅读模式，退出后仍是阅读模式。
- 原本关闭的 ActivityBar 或其他可配置区域，不得被禅模式强制打开。

**禅模式应作为展示层覆盖，而不是改写原始布局状态。**

### 6.3 Focus Width 兼容

现有 Focus Width 和 Zen Mode 是两个独立概念：

- Focus Width 仅控制正文宽度。
- Zen Mode 控制整个工作区的可见性与布局。

进入禅模式时可以临时采用适合沉浸写作的宽度，但不得修改现有 Focus Width 用户设置。

退出后恢复原有宽度设置。

### 6.4 导航与退出

V1 采用文档级生命周期：

- 同一文档内编辑、阅读切换：保持禅模式。
- 当前文档发生普通自动保存：保持禅模式。
- 打开另一篇文档：退出禅模式。
- 导航到 Calendar Home：退出禅模式。
- 进入 Board / Ledger / Settings 等其他工作区：退出禅模式。
- 进入 History / Diff / Recovery 专用视图：退出禅模式。
- 浏览器后退或前进导致文档变化：退出禅模式。
- 刷新页面：不恢复禅模式。

不能通过清空文档 Tab 或销毁编辑器来实现退出。

## 7. 数据安全与 Diary 边界

### 7.1 保存机制

Zen Mode 不修改以下行为：

- 自动保存。
- 手动保存。
- 浏览器草稿持久化。
- 外部文件变更检测。
- 保存冲突。
- Crash Recovery。
- History / Git 提交规则。

普通保存成功时，不要求额外显示状态。

当发生保存失败、离线或外部冲突时，不允许静默掩盖风险。必须沿用现有错误提示与恢复能力；必要时退出禅模式，暴露原有冲突处理界面。

### 7.2 Diary 安全要求

Zen Mode 必须完整遵守当前 Diary 约束：

- 不绕过 Diary 密码验证。
- 不改变 Diary 解锁 Session。
- 不产生第二个 managed Diary 文档实例。
- 不复制解密后的内容到额外状态或持久存储。
- 不改变 Diary 单文档切换前的保存保护。
- Diary 被锁定、会话失效或离开当前文档时，及时终止禅模式。
- 不改变 Diary Calendar 和顶部日期按钮的返回规则。

### 7.3 生命周期

Zen Mode 不能成为新的文档生命周期所有者。

文档仍由 Vault 已有的 Tab、Editor、Reading 和保存机制管理。

切换模式不得额外创建文档实例、执行网络请求或生成版本记录。

## 8. 异常与边界行为

| 场景 | 预期 |
| --- | --- |
| 禅模式期间自动保存成功 | 无干扰，继续编辑 |
| 保存失败 | 提示错误并保留恢复能力 |
| 外部文件冲突 | 退出禅模式或立即呈现原有处理入口 |
| 当前文档被删除 | 退出禅模式，沿用原有错误处理 |
| Diary 会话锁定 | 退出禅模式 |
| 进入其他文档 | 退出禅模式 |
| 浏览器刷新 | 使用普通布局恢复 |
| 进入禅模式后改变窗口宽度 | 保持禅模式，并按当前可视区域重新布局 |
| 浏览器失去焦点 | 不退出禅模式 |
| 切换 Light / Dark | 沿用当前应用主题 |
| 编辑器正在输入法组合输入 | 不拦截输入，不错误退出 |

## 9. 快捷键与兼容性

现有快捷键不得被覆盖，包括：

- `Cmd/Ctrl + S`：保存
- `Cmd/Ctrl + W`：关闭文档
- `Cmd/Ctrl + B`：侧栏
- `Cmd/Ctrl + E`：阅读 / 编辑模式
- `Ctrl/Cmd + K → Z`：切换 Zen Mode
- `Cmd/Ctrl + P`：全局搜索
- `G → B`：Diary 返回操作

Markdown 链接仍可从 Monaco 上下文菜单插入；`[[` Wiki Link 行为不变。

特别要求：

1. 禅模式不能劫持 Monaco 的编辑快捷键。
2. 禅模式不覆盖原有全局搜索。
3. 不为了新增 Zen Mode 而重构现有搜索面板。
4. 不干扰 Diary 快捷键状态机。
5. 在中文和英文输入法环境下保持行为一致。

快捷键方案在正式实施前需要完成一次跨平台冲突验证。

## 10. 验收标准

### AC-01：进入条件

桌面、平板和手机上的 Note 与已解锁 Diary 文档能够进入禅模式。

Vault Home、Calendar Home、Ledger、Board 及特殊恢复视图不能错误进入禅模式。

### AC-02：界面隐藏

进入后，NavBar、ActivityBar、FileTree、RightRail、EditorTabs 与 StatusBar 不可见且不占用布局空间。

正文在可用区域居中显示。

### AC-03：布局恢复

在不同侧栏组合下连续进入与退出禅模式，原有布局设置完全保留。

### AC-04：文档完整性

进入和退出不改变文档内容，不触发额外保存，不清空撤销栈，不替换编辑器模型。

### AC-05：阅读模式

在阅读模式中进入与退出，不改变阅读状态及 Markdown 渲染行为。

### AC-06：快捷键

Zen Mode 快捷键与现有编辑快捷键不冲突，Escape 优先级正确。

### AC-07：Diary

Diary 禅模式不破坏密码保护、单文档策略和返回日历逻辑。

### AC-08：生命周期

切换 Workspace、切换文档、会话失效和浏览器刷新后，不残留错误的禅模式布局。

### AC-09：异常处理

保存失败与文件冲突仍可发现、处理和恢复，不发生静默数据丢失。

### AC-10：回归验证

必须覆盖：

- Light / Dark。
- Chrome / Safari；触控入口重点检查 iPhone 与 iPad Safari 的 Pointer Events 行为。
- macOS / Windows 键盘交互。
- Monaco 编辑与阅读状态。
- Note 与 Diary。
- 未保存修改与自动保存。
- 输入法、弹窗和 Escape 优先级。
- 375px 手机、768px / 1024px 平板的宽度变化与布局边界。

运行现有类型检查、单元测试及相关 E2E，确保不引入新回归。

## 11. 实施约束

1. 优先复用现有 Vault 组件和状态所有者。
2. 以最小范围的展示状态与样式调整实现。
3. 不创建新的 Editor 或 Reading 组件。
4. 不引入新的全局持久化状态。
5. 不新增后端 API 或数据库字段。
6. 不改变 Markdown 渲染器。
7. 不修改 Diary 和 Ledger 业务规则。
8. 不新增常驻顶部工具栏。
9. 不改变普通模式下现有移动端布局；禅模式只在临时状态下隐藏辅助界面并适配可视高度。
10. 新增测试优先验证行为契约，不依赖易变的 DOM 层级。

## 13. 成功标准

Zen Mode 的成功不以新增多少交互组件衡量，而以以下结果衡量：

1. 用户能够快速进入沉浸式阅读或写作。
2. 用户不需要学习新的编辑器操作。
3. 用户退出后能够无感恢复原有工作区。
4. 禅模式不增加数据丢失或恢复失败风险。
5. 功能实现没有显著增加 Vault 的状态复杂度。

**最终目标：让 Nuvyn 在需要的时候退到背景中，让文档内容成为界面唯一的主角。**

### 我认为评审时最重要的两点

第一，禅模式应该是临时的，不应记忆到下次启动。这样不会在重新打开 Nuvyn 时意外隐藏文件树、日记日历等必要界面。

第二，早期草案中的快捷键入口曾待定。我已确认 `Cmd/Ctrl+K` 和 `Cmd/Ctrl+P` 存在既有用途；实际实现保留两段式 `Ctrl/Cmd+K → Z`，本次 Logo 入口不会替换它。

## 增量补充 — Logo 星座入口与移动端支持（2026-10-11）

本补充记录在既有 V1 禅模式基础上的新增范围，不重做编辑器、快捷键、保存或 Diary 生命周期。早期“不支持移动端”以及窗口缩至移动断点时自动退出的决定由本补充 supersede；普通模式的移动端导航和布局仍保持原样。

- 桌面鼠标悬停 Logo 3 秒；手机和平板触摸长按 Logo 3 秒，启动现有 9 节点星座动画。
- 触摸位移超过 12px、长按前抬手或 `pointercancel` 会取消识别；长按识别成功后松手不打断动画。页面隐藏、路由改变、失焦、Escape、卸载仍会清理动画状态。
- 普通点击仍回首页，长按触发后的合成 click 被消费一次，防止误导航；触控处理仅作用于 Logo，允许页面其余区域正常滚动。
- 只以最后一个节点的有限 CSS 入场动画完成作为动画完成依据，不等待光环、连线或粒子的无限循环。系统减少动态效果时不等待已禁用的动画事件。
- 资格判断仍归 VaultView 所有。动画淡出完成后再次检查有效文档、Workspace 和 Diary 解锁状态，再启用禅模式；失效时不进入。
- 手机和平板的禅模式只呈现正文，不保留 NavBar、ActivityBar、树、RightRail、Tab 和 StatusBar 的布局占位；按动态视口高度与安全区域布局。刷新仍回到普通模式，不新增移动端退出控件或手势。

除此之外，我倾向于保持这份 PRD 的 V1 边界，不增加更多功能。
