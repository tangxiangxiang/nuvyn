# Note Tablet Phase 2 — 触摸编辑

适用范围：Note 编辑模式、601–1199px。沿用 Phase 1.1 的单文档展示和工作区文档状态。

## 实现边界

- Monaco 原生负责光标、选区、触摸滚动、Undo/Redo；继续使用现有 TextModel 缓存、View State 和自动布局。
- Visual Viewport 的 resize/scroll 与窗口 resize 合并到动画帧，按实际可视底边约束 Vault 高度。没有 Visual Viewport 时使用原有 dvh；缩放手势不按键盘处理。退出编辑、打开抽屉/设置及卸载时释放协调监听和样式。
- 高度缩小后，仅对仍有输入焦点且已被遮挡的光标执行最小滚动，不设置选区，不主动唤起键盘。
- 合成输入期间停止向 Tab 同步正文和触发 Markdown 补全/写作诊断；首次实际文本变化只调用原有 Pin，避免干净 Preview 替换丢失尚未提交的输入，结束时同步最终文本并去重。平板合成过程中不以外部 props 重置 Model。切换、关闭、路由更新以及离开输入区域、模式退出或卸载时保留尚未同步的 Model 文本，使用来源路径交回原有保存与草稿机制。未收到系统 compositionend 的边界行为需要真机确认。
- NavBar 编辑操作区提供图片按钮（现有 Photo 图标和 Naive UI），调用 EditorPane.chooseImage。原有 Picker、Tracked Range、Generation 校验和复制 Markdown 回退继续负责上传和插入。

视口调整不会修改文本或触发保存。阅读模式、桌面、手机、Diary 及特殊只读视图不提供该平板图片入口。

## 自动化验证范围

`note-tablet-edit.spec.ts` 验证真实 Monaco 的触摸入口、文本同步、Preview 固定、保存、布局/Model 身份、长文档、抽屉、Undo/Redo、图片插入及上传中跨文档保护。现有 tablet 配置同时收集该文件和 Phase 1 测试，使用 Chromium / WebKit。

视口缩小测试是浏览器几何回归，不等同于系统软键盘。单元测试中的 Visual Viewport 和 Composition 信号只验证应用逻辑，不代表真实中文候选系统。
